# Stage 9.2-H2: 遗留问题与已知边界报告 (Remaining Issues)

## 一、时基审查与已澄清项

### 1. 内核 Tick (100 Hz) 与硬件 TIM2 (1000 Hz) 严格分离
在 Stage 9.2-H1 测试中，`g_sys_tick` 与 `g_tim2_ms_count` 均在 `TIM2_IRQHandler` 中递增，导致报告将 1000 Hz 的 TIM2 计数误冠以 `sys_tick` 之名。
**本阶段核实澄清**：
- **RTOS 内核调度时基**：由 Cortex-M3 SysTick 提供，频率严格为 **100 Hz**，对应内核内部变量 `kernel_ticks`（通过 `rtos_tick_get()` 访问），实机 60 秒增量约 6,100。
- **硬件高精度毫秒时基**：由通用定时器 TIM2 提供（PSC=71, ARR=999），频率严格为 **1000 Hz**，对应变量 `g_tim2_ms_count`，实机 60 秒增量约 61,000。
两套时钟在硬件上独立运行，报告与脚本中均已严格区分并独立测量记录。

### 2. Mutex 依赖验证与 Generation 语义边界
`rtos_diag_dl_verify_current()` 的 generation 验证保证了快照捕获时各任务对象的有效性（未被销毁或槽位复用），但**并不等同于在后续任意时刻整个系统的 Mutex 等待拓扑都保持静止不变**。诊断结果代表短临界区（< 3 µs）捕获时刻的系统图快照。本设计符合实时嵌入式诊断的无锁观察语义。
