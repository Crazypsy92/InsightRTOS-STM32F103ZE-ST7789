# Stage 9.2-H2: 16×16 中文点阵字体集成与渲染架构报告 (Chinese Font Report)

## 一、字模规格与集成原则

- **点阵规格**：16×16 像素，单色 1 bit/pixel（每字 32 字节）。
- **编码排版**：标准 UTF-8 编码，3 字节 CJK 字符自动识别；与 8×16 基础 ASCII 字体混排在同一基线（行高 16 像素）。
- **字形来源**：Noto Sans CJK SC Regular（SIL Open Font License 1.1），开发主机预生成 118 个精选高频诊断与交互汉字，运行时固化在 Flash 中，**零动态内存分配**。
- **体系结构隔离**：字模数据与渲染例程（`lcd_cn16.c`、`lcd_cn16.h`）严格存放在硬件 BSP/显示层，**禁止侵入 InsightRTOS 公共内核**。
- **独占渲染原则**：所有字符解包与 `LCD_ShowPicture()` 传输严格由 `LCD Task` 独占调用，绝不在中断、SysTick、PendSV 或业务任务中跨线程并发访问。

---

## 二、批量总线传输与显存开销

1. **显存与批量缓冲**：
   - 避免每像素或单线触发独立 SPI 传输，复用单字 512 字节（16×16×2 RGB565）静态本地缓冲，通过 `LCD_ShowPicture()` 一次性向 ST7789 突发传输。
   - 消除全屏 FrameBuffer（节省 240×240×2 = 115.2 KiB 昂贵 SRAM，适配 STM32F103 64 KiB 物理 RAM 边界）。
2. **Flash 与 SRAM 增量测量**：
   - 字模表尺寸：118 字 × 34 字节（2 字节 unicode + 32 字节位图）= 4,012 字节常量数据。
   - 固件 Flash 变化：由 Stage 9.2-H1 的 43,620 字节增加到 46,564 字节（净增 2,944 字节，含字模与 UTF-8 解码驱动），仅占用 23 页 Flash，远低于 31 页上限。
   - 运行时 SRAM 增加：0 字节动态分配，仅占用 512 字节局部单任务字模转换静态缓冲。

---

## 三、字符渲染与边界安全

1. **UTF-8 字符边界校验**：严格校验 3 字节 UTF-8 编码前导位 `0xE0~0xEF` 及后续字节合法性，避免多字节字符截断错乱。
2. **未收录字符优雅降级**：若遇到未收录汉字或异常字节，自动降级渲染为 ASCII `'?'` 字符（步进 8 像素），不发生内存越界、无静默吞字、无画面乱码。
3. **差分行显存缓冲**：采用 15 行 × 64 字节文本影子缓冲（`previous_cons`），仅在行文本或颜色变更时调用 SPI 绘制，静态无变化时 SPI 总线负载为 0%。
