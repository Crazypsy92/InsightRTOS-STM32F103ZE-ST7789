# Stage 9.2-H1: 硬件复位与自恢复实机测试报告 (Reset Test)

## 一、测试目标与流程

验证 STM32F103ZET6 在完成 Stage 9.2 固件烧录与长时间运行后，执行系统硬件复位（`reset run`）能够正确重启，恢复多任务调度与 ST7789 显存渲染，且不遗留错误状态。

---

## 二、复位操作与实机观测

1. **复位触发**：通过 OpenOCD DAP 接口向 MCU 发送 `reset run` 指令。
2. **启动时序与初始状态检查**：复位释放后延时 2 秒进行非侵入式内存读取。

### 复位后内存状态核验
- **`g_sys_tick` (复位后内核 Tick)**: **2,053**（复位已成功发生，时钟从 0 重新递增至约 2 秒）。
- **`g_tim2_ms` (复位后定时器)**: **2,054**（TIM2 硬件时钟重新同步同步）。
- **`lcd_refreshes` (屏幕刷新计数)**: **5**（复位后已完成 5 次初始局部差分渲染）。
- **任务运行计数**:
  - `KEY`: 0（就绪等待按键中断事件，正常）。
  - `Controller`: 206（以 10ms 周期执行，2 秒内约 200 次，正常）。
  - `LCD`: 5（以 250ms 周期刷新，2 秒内 5 次，正常）。
  - `Monitor`: 4（以 500ms~1s 节拍执行，2 秒内 4 次，正常）。
- **错误与断言**:
  - `transport_errors`: 0
  - `initialization_errors`: 0
  - `g_rtos_assert_expression`: 0 (无任何断言失败)

---

## 三、复位测试结论

1. 硬件复位正常释放，MCU 自 `0x08000000` 正常重新执行复位向量。
2. 内部外设（SPI3、DMA2、TIM2、GPIO、NVIC）正确完成二次初始化。
3. InsightRTOS 调度器正常启动，各任务控制块（TCB）、静态就绪队列及诊断工作区重新建立。
4. ST7789 屏幕无花屏、无总线挂起，正常进入持续更新状态。

**判定：PASS**
