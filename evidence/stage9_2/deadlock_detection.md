# Stage 9.2: 死锁环路检测算法与验证 (Deadlock Detection)

## 1. 算法背景与数学模型
在 InsightRTOS 中，互斥量等待关系构成有向图 $G = (V, E)$：
- **顶点集 $V$**：当前活动任务节点集合（$|V| \le 8$）。
- **有向边集 $E$**：$u \to v$ 表示任务 $u$ 正在阻塞等待互斥量 $M$，而该互斥量当前被任务 $v$ 持有。
- **出度约束**：由于每个任务同一时刻至多只能阻塞等待一个互斥量，图 $G$ 中每个顶点的出度至多为 1（$\text{out-deg}(v) \le 1$）。

该图性质使得死锁环路检测具备确定性线性时间复杂度 $O(|V|)$，无需复杂的大图遍历算法。

## 2. 深度优先三色染色循环检测算法
在 `rtos_diag_dl_analyze` 中，利用工作区内部的 `scratch` 数组（24 字节），实现了无动态分配的有界三色 DFS：

- `0` (White - 未访问)：该节点尚未探索。
- `1` (Gray - 探索中/在当前调用栈路径上)：若在探索出边时遇到 Gray 节点，则证明发现反向边，**存在环路（死锁）**！
- `2` (Black - 已探索完成/确定无环)：已确认为无环分量，后续遍历直接剪枝。

### 2.1 循环提取与规范化旋转 (Canonical Rotation)
当检测到反向边（指向 Gray 节点）时：
1. 从当前探索路径栈 `path` 中提取出环路切片：从环路起点 `cycle_start` 至当前节点。
2. 规范化旋转：寻找环中任务插槽号最小的节点（$\min(\text{slot})$），将其旋转至输出数组 `cycle_tasks[0]`。这保证了环路输出的唯一性与确定性，方便单元测试断言与前端稳定渲染。
3. 统计环上有限等待边（`RTOS_DIAG_DL_EDGE_FINITE`）数量，记录最早将超时的 Tick 计数器 `earliest_due_tick`。
4. 设置结果标志位：
   - `RTOS_DIAG_DL_RES_DEADLOCK`: 确认死锁。
   - `RTOS_DIAG_DL_RES_HAS_TIMEOUT`: 环中存在带超时的等待边（死锁可在未来自动打破）。

### 2.2 不完整与异常图防护
若在捕获阶段检测到快照异常（如任务意外丢失、自锁异常、不完整快照）：
- 设置结果标志 `RTOS_DIAG_DL_RES_ANOMALY` 与 `RTOS_DIAG_DL_RES_INCOMPLETE`。
- **绝对不向用户或调用方报告 NO DEADLOCK**，确保不会产生假阴性安全隐患。

## 3. 算法复杂度与边界防护
- **时间复杂度**：每个节点至多被访问常数次，总步数 $\le 2 \times 8 = 16$ 步。执行耗时小于 1 µs。
- **空间复杂度**：$O(1)$，仅使用工作空间固定的 24 字节 scratch 数组，调用栈深度不超过 8 帧。
- **上下文限制**：仅在任务（线程）上下文中允许执行。通过 `rtos_port_in_handler()` 严密拦截中断上下文调用，违规返回 `RTOS_ERR_CONTEXT`。

## 4. 实时快照验证 (`rtos_diag_dl_verify_current`)
从快照捕获到实际采取诊断或恢复动作之间，系统可能已经发生调度或任务状态迁移。
`rtos_diag_dl_verify_current` 提供轻量级一致性验证：
- 在微秒级关中断临界区内，校验快照中每个节点的插槽世代号。
- 若任务已退出（`RTOS_TASK_TERMINATED` 或 `RTOS_TASK_UNUSED`），或插槽已被新任务复用（世代号增加），立即返回 `RTOS_ERR_STALE`。
- 确保系统永远不会基于过期陈旧的死锁快照进行判断。
